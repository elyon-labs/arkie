# CS2 RCON Front End

`cs2_rcon_front_end` is a Flutter desktop UI that wraps the `cs2_rcon_client` package so you can save CS2 servers, open an RCON console per server, and monitor connection health without leaving a GUI.

## What the app currently provides

- Save multiple CS2 servers (name, address, port, password) locally via `RxSharedPreferences`.
- Select a server to open a live RCON console with a scrolling transcript of client/server messages.
- Continuous connection monitoring (`echo ping` every 5 seconds) with automatic reconnection attempts and a visible status indicator.
- An “Add server” dialog with validation plus a settings view that can clear all saved servers in one tap.
- A single code path shared with the CLI by depending directly on `packages/client`, ensuring the UI and terminal behave consistently.

## Requirements

- Flutter 3.35.7+ (which includes Dart >=3.9.0) with your target desktop platform enabled (`flutter config --enable-macos-desktop`, etc.).
- Access to a CS2 server with RCON enabled and reachable from your machine (default port `27015`).
- The monorepo bootstrapped with Melos so the local path dependency on `../packages/client` can be resolved.

## Run locally

```bash
cd apps/front_end
flutter pub get
flutter run -d macos        # swap macos for windows/linux as needed
```

On first launch, use the “Add server” button in the sidebar to save a target. Selecting a server instantiates an `RCONCubit`, connects using the stored credentials, and streams responses into the message list. Type commands into the input at the bottom; each enter keypress sends the command via the shared `cs2_rcon_client`. Use the settings section to clear the saved list if you ever need to reset the local preferences.

## Building for distribution

```bash
flutter build macos   # or flutter build windows / flutter build linux
```

Release artifacts land in the standard Flutter `build/<platform>` folders.

## Architecture notes

- **State management** – `flutter_bloc` powers `ServersCubit` (server list) and `RCONCubit` (live console). `safeEmit` helpers avoid state emissions after disposal.
- **Persistence** – `ServersRepository` wraps `RxSharedPreferences` so server definitions survive restarts. All serialization is generated by `dart_mappable`.
- **Dependency injection** – `get_it` is bootstrapped in `di/graph.dart` and keeps repositories single-scoped across the app.
- **Networking** – All RCON traffic flows through `cs2_rcon_client`, so the UI benefits from the same packet handling, logging, and error types as the CLI.

### Troubleshooting

- **Stale servers** – Use the Settings → “Clear server list” action to wipe preferences, or delete the `servers` key from the host OS’s shared preferences store.
- **Connection loops** – `RCONCubit` retries automatically but stops monitoring if reconnection fails; tap “Reconnect” next to the error message to try again manually.
