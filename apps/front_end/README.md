# CS2 RCON Front End

`cs2_rcon_front_end` is a Flutter desktop UI that wraps the `cs2_rcon_client` package so you can save CS2 servers, open an RCON console per server, and monitor connection health without leaving a GUI.

## What the app currently provides

- Save multiple CS2 servers (name, address, port, password) locally via `RxSharedPreferences`.
- Select a server to open a live RCON console with a scrolling transcript of client/server messages.
- Continuous connection monitoring (`echo ping` every 5 seconds) with automatic reconnection attempts and a visible status indicator.
- An “Add server” dialog with validation plus a settings view that can clear all saved servers in one tap.
- A single code path shared with the CLI by depending directly on `packages/client`, ensuring the UI and terminal behave consistently.

## Requirements

- Flutter 3.35.7+ (which includes Dart >=3.9.0) with your target desktop platform enabled (`flutter config --enable-macos-desktop`, etc.).
- Access to a CS2 server with RCON enabled and reachable from your machine (default port `27015`).
- The monorepo bootstrapped with Melos so the local path dependency on `../packages/client` can be resolved.

## Run locally

```bash
cd apps/front_end
flutter pub get
flutter run -d macos        # swap macos for windows/linux as needed
```

On first launch, use the “Add server” button in the sidebar to save a target. Selecting a server instantiates an `RCONCubit`, connects using the stored credentials, and streams responses into the message list. Type commands into the input at the bottom; each enter keypress sends the command via the shared `cs2_rcon_client`. Use the settings section to clear the saved list if you ever need to reset the local preferences.

## Building for distribution

```bash
flutter build macos   # or flutter build windows / flutter build linux
```

Release artifacts land in the standard Flutter `build/<platform>` folders.

### macOS

Arkie is distributed with a Developer ID signature and an Apple notarisation rather than through
the Mac App Store, so a release goes out when it is ready instead of when App Review says so.
Notarisation is an automated malware scan, not a review — it has no concept of a demo server to
give a reviewer.

`macos/packaging/make-dmg.sh` is the whole lane: it builds, signs inside out with the hardened
runtime, lays out a .dmg with an Applications symlink, notarises it and staples the ticket on.
Stapling is what lets a Mac open the image without phoning Apple first. The script takes its
credentials from the environment and holds none of its own, which is what keeps it in the public
tree alongside `windows/ci/cs2-rcon.iss` and `linux/packaging/deb/make_config.yaml`; the private
deployment repository supplies them. `SKIP_NOTARIZE=1` stops after signing, for checking a build
without credentials.

The app stays sandboxed. The sandbox is optional under Developer ID, but it works today and
turning it off would move preferences out of the app's container, losing the saved servers of
anyone already running it. Nothing else here depends on dropping it. What the lane does add is
`ENABLE_HARDENED_RUNTIME`, which the notary service refuses a submission without.

The one thing the store used to provide and this does not is updates. Until the app checks for
them itself, the download page is the only thing that knows a newer version exists.

## Architecture notes

- **Shared packages** – Everything the mobile app also needs lives in a package rather than here: data, domain and dependency injection in `packages/core` (`arkie_core`), cubits in `packages/state` (`arkie_state`), and the theme in `packages/ui` (`arkie_ui`). This app keeps its widgets and the desktop-only settings, theme-mode and privacy-mode features.
- **State management** – `flutter_bloc` powers `ServersCubit` (server list) and `RCONCubit` (live console), both from `arkie_state`. `safeEmit` helpers avoid state emissions after disposal.
- **Persistence** – `ServersRepository` (in `arkie_core`) stores server definitions in Hive so they survive restarts. All serialization is generated by `dart_mappable`.
- **Dependency injection** – `get_it` is bootstrapped in `arkie_core`'s `di/graph.dart` and keeps repositories single-scoped across the app.
- **Theme** – `buildDesktopTheme(ArkieTheme.desktopLight / desktopDark)` from `arkie_ui`. Widgets read colours with `context.colors` and text styles with `context.text`, and lay out with `Sizes`, `HSpace` and `VSpace` from the Elyon Labs design package.
- **Networking** – All RCON traffic flows through `cs2_rcon_client`, so the UI benefits from the same packet handling, logging, and error types as the CLI.

### Icons

`assets/icon.svg` is the source of truth for every Arkie icon, including the website's favicon.
Two steps turn it into what each platform wants, and both are run by hand because everything they
produce is committed:

1. `pnpm app:icon:render` from the repository root rasterises it with headless Chrome into
   `assets/icon.png`, the plate at full bleed for the Debian package; `assets/icon-macos.png`,
   inset to Apple's icon grid because macOS draws app icons inside a smaller box than their
   canvas and expects the art to carry its own rounded shape; and
   `windows/runner/resources/app_icon.ico`.
2. `dart run flutter_launcher_icons` from this directory pushes the macOS PNG into
   `macos/Runner/Assets.xcassets`.

The `.ico` is written by the render script rather than by `flutter_launcher_icons`, which emits a
single size. Windows asks for nine, from 16 in a title bar to 256 in Explorer's jumbo view, and
downscales from whatever it can find when one is missing — a file holding 48 alone left the icon
soft everywhere else. Each size is rasterised from the vector rather than resampled from a big
PNG, which matters most at 16 and 20. Adding `windows:` back to `flutter_launcher_icons.yaml`
would overwrite all of it.

The script overrides `#plate` and `#mark` per target rather than editing the SVG, so keep both
ids. The colours are `background` and `accent` from `lib/core_ui/colors.dart` — change them there
and here together.

The website keeps its own copy at `apps/web/public/icon.svg`; copy it across if the icon changes.

### Troubleshooting

- **Stale servers** – Use the Settings → “Clear server list” action to wipe preferences, or delete the `servers` key from the host OS’s shared preferences store.
- **Connection loops** – `RCONCubit` retries automatically but stops monitoring if reconnection fails; tap “Reconnect” next to the error message to try again manually.
